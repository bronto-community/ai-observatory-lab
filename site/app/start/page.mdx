# Start here

## What you need

<Requirements />

Everything the labs need goes into one `.env` file. Pick your LLM route below: the choice is remembered, and both
labs follow it.

<OneAtATime />

## 1. Bronto

<Steps>
<Step n="1.1" title="A Bronto account" then="you're in the Bronto app.">

Already have one? Use it. Otherwise sign up at [bronto.io/signup](https://bronto.io/signup) for a **trial, no credit
card needed**, with Google or email, in the **EU or the US**. Either works: note which one. Your browser shows it once
you're in: `app.eu.bronto.io` or `app.us.bronto.io`.

This is **your** account: Track A sends your agent's telemetry here and builds its dashboard here. (Track B's agent
reads a shared demo org instead, with a key that's on the Track B page.)

</Step>
<Step n="1.2" title="Two Bronto API keys" then="you have both keys saved somewhere safe.">

In Bronto, go to **Settings → API Keys** ([docs](https://docs.bronto.io/Account-Management/API-Keys)) and create:

- an **ingestion** key: your agent sends its telemetry with it;
- a key that can **create dashboards**, used once in Track A to build the LLM dashboard.

</Step>
</Steps>

## 2. Your LLM

<LLMTabs>
<Tab label="AWS Bedrock">

Amazon Bedrock, billed to your AWS account: the labs use a few cents of tokens. They only use models that need
**no access form**: Amazon Nova 2 Lite and OpenAI's gpt-oss-120b.

<Callout tone="tip" title="Your AWS region">
The commands use **us-west-2 (Oregon)**: it has every model and feature the labs touch, including AgentCore. Prefer
one closer to you? Replace `us-west-2` in the commands and in `.env` with, for example, `us-east-1`, `eu-west-1`,
`eu-central-1` or `ap-northeast-1`. Nova 2 Lite runs as a **global** profile (`global.amazon.nova-2-lite-v1:0`), so
the same model ID works from any of them, though AWS may serve a request from another region. gpt-oss-120b runs in
the region you pick.
</Callout>

<Steps>
<Step n="2.1" title="An AWS account" then="you can sign in to the AWS console.">

Already have one? Use it. Otherwise sign up at [aws.amazon.com/free](https://aws.amazon.com/free/), which has the
current offer for new accounts. Turn on MFA for the root user (console → your account name → **Security
credentials**).

</Step>
<Step n="2.2" title="The AWS CLI v2" then="aws --version prints aws-cli/2.x.">

<OSTabs>
<Tab label="macOS / Linux">

macOS with Homebrew:

```bash
brew install awscli
```

Linux (x86_64; use `aws-cli-linux-aarch64` on ARM):

```bash
curl -sSL "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o awscliv2.zip && unzip -q awscliv2.zip && sudo ./aws/install
```

</Tab>
<Tab label="Windows (PowerShell)">

```powershell
msiexec.exe /i https://awscli.amazonaws.com/AWSCLIV2.msi
```

Close and reopen PowerShell after the installer finishes.

</Tab>
</OSTabs>

```bash
aws --version
```

</Step>
<Step n="2.3" title="Sign the CLI in" then="your browser says you're logged in.">

This opens your browser, signs in with your console login, and gives the CLI short-lived credentials:

```bash
aws login --region us-west-2
```

If `aws login` isn't recognised, update the AWS CLI (step 2.2). If your company signs you in with IAM Identity
Center instead, use `aws sso login --profile YOUR-PROFILE` and add `--profile YOUR-PROFILE` to the `aws` commands
below.

</Step>
<Step n="2.4" title="Check who you are" then="you see your 12-digit account ID.">

```bash
aws sts get-caller-identity
```

</Step>
<Step n="2.5" title="Check Bedrock from the CLI" then="the model replies with a short greeting.">

<OSTabs>
<Tab label="macOS / Linux">

```bash
aws bedrock-runtime converse --region us-west-2 --model-id global.amazon.nova-2-lite-v1:0 --messages '[{"role":"user","content":[{"text":"Say hello in five words"}]}]' --query 'output.message.content[0].text' --output text
```

</Tab>
<Tab label="Windows (PowerShell)">

PowerShell mangles JSON quotes passed to programs, so put the message in a file first:

```powershell
'[{"role":"user","content":[{"text":"Say hello in five words"}]}]' | Set-Content -Encoding ascii msg.json
aws bedrock-runtime converse --region us-west-2 --model-id global.amazon.nova-2-lite-v1:0 --messages file://msg.json --query "output.message.content[0].text" --output text
```

</Tab>
</OSTabs>

</Step>
</Steps>

</Tab>
<Tab label="Your own API key">

No AWS account or AWS CLI needed.

<Callout tone="tip" title="No key yet? Use Google Gemini's free tier">
A Gemini API key on Google's [free tier](https://ai.google.dev/gemini-api/docs/billing) covers both labs at no
cost, with no billing account. Two things to know: the free tier has rate limits (if you see a `429` or
`RESOURCE_EXHAUSTED` error, wait a minute and ask again), and Google may use free-tier prompts and answers to improve
its products, so don't send anything private. With OpenAI or Anthropic, your provider bills you; the labs use a
few cents of tokens.
</Callout>

<Steps>
<Step n="2.1" title="An API key from one provider" then="you have the key saved somewhere safe.">

- **Google** (free tier, recommended): [aistudio.google.com/apikey](https://aistudio.google.com/apikey). Sign in
  with a Google account and **Create API key**. The labs use `gemini-3.8-flash`.
- **OpenAI**: [platform.openai.com/api-keys](https://platform.openai.com/api-keys). The labs use `gpt-5.4-mini`.
- **Anthropic**: [console.anthropic.com/settings/keys](https://console.anthropic.com/settings/keys). The labs use
  `claude-haiku-4-5-20251001`.

OpenAI and Anthropic need prepaid credit on the account before the key works.
More on models: [Your own LLM key](/byo-llm).

</Step>

## 4. Make your `.env`

<Steps>
<Step n="4.1" title="A folder and a .env file" then="the folder has a .env file in it.">

Replace the placeholders before you paste: your **ingestion key** and your **name** (lowercase, no spaces). With a
**US** Bronto account, change `BRONTO_REGION=eu` to `BRONTO_REGION=us`.

<LLMTabs>
<Tab label="AWS Bedrock">

<OSTabs>
<Tab label="macOS / Linux">

```bash
mkdir ai-observatory && cd ai-observatory
cat > .env <<'EOF'
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
AWS_SESSION_TOKEN
AWS_REGION=us-west-2
BRONTO_REGION=eu
OTEL_EXPORTER_OTLP_HEADERS=x-bronto-api-key=YOUR-INGESTION-KEY
ATTENDEE=yourname
EOF
```

</Tab>
<Tab label="Windows (PowerShell)">

```powershell
mkdir ai-observatory; cd ai-observatory
@"
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
AWS_SESSION_TOKEN
AWS_REGION=us-west-2
BRONTO_REGION=eu
OTEL_EXPORTER_OTLP_HEADERS=x-bronto-api-key=YOUR-INGESTION-KEY
ATTENDEE=yourname
"@ | Set-Content -Encoding ascii .env
```

Keep `-Encoding ascii`: otherwise Windows PowerShell 5.1 can add a byte-order mark and Docker misreads the first line.

</Tab>
</OSTabs>

The three bare `AWS_…` lines have no values on purpose: Docker copies them from your terminal (next step).

</Tab>
<Tab label="Your own API key">

Put in your LLM key too. The example is for Google Gemini. For OpenAI, use the lines `LLM_PROVIDER=openai` and
`OPENAI_API_KEY=…`; for Anthropic, `LLM_PROVIDER=anthropic` and `ANTHROPIC_API_KEY=…`.

<OSTabs>
<Tab label="macOS / Linux">

```bash
mkdir ai-observatory && cd ai-observatory
cat > .env <<'EOF'
LLM_PROVIDER=gemini
GEMINI_API_KEY=YOUR-LLM-KEY
BRONTO_REGION=eu
OTEL_EXPORTER_OTLP_HEADERS=x-bronto-api-key=YOUR-INGESTION-KEY
ATTENDEE=yourname
EOF
```

</Tab>
<Tab label="Windows (PowerShell)">

```powershell
mkdir ai-observatory; cd ai-observatory
@"
LLM_PROVIDER=gemini
GEMINI_API_KEY=YOUR-LLM-KEY
BRONTO_REGION=eu
OTEL_EXPORTER_OTLP_HEADERS=x-bronto-api-key=YOUR-INGESTION-KEY
ATTENDEE=yourname
"@ | Set-Content -Encoding ascii .env
```

Keep `-Encoding ascii`: otherwise Windows PowerShell 5.1 can add a byte-order mark and Docker misreads the first line.

</Tab>
</OSTabs>

Your `.env` now holds a secret: don't commit it or paste it anywhere public.

</Tab>
</LLMTabs>

</Step>
<Step n="4.2" title="AWS route only: put your credentials in this terminal" then="the command prints nothing (that's success).">

<LLMTabs>
<Tab label="AWS Bedrock">

Run this in every new terminal you start an agent from, and again when the credentials expire (the doctor tells
you):

<OSTabs>
<Tab label="macOS / Linux">

```bash
eval "$(aws configure export-credentials --format env)"
```

</Tab>
<Tab label="Windows (PowerShell)">

```powershell
aws configure export-credentials --format powershell | Invoke-Expression
```

</Tab>
</OSTabs>

</Tab>
<Tab label="Your own API key">

Nothing to do: your key is already in `.env`. Skip to the doctor.

</Tab>
</LLMTabs>

</Step>
<Step n="4.3" title="Run the doctor" then="it ends with “All good”.">

```bash
docker run --rm --env-file .env ghcr.io/bronto-community/track-a-agent python doctor.py
```

It makes a real call to your model (through Bedrock, or with your key) and checks that Bronto accepts your
ingestion key.

</Step>
</Steps>
