# Start here

## What you need

<Requirements />

Everything the labs need goes into one `.env` file. Pick your LLM route below: the choice is remembered, and both
labs follow it.

<OneAtATime />

## 1. Bronto

<Steps>
<Step n="1.1" title="A Bronto account" then="you're in the Bronto app.">

Already have one? Use it. Otherwise sign up at [bronto.io/signup](https://bronto.io/signup) for a **14-day trial, no
credit card**, with Google or email. Note your **region**, EU or US: your ingestion address depends on it.

</Step>
<Step n="1.2" title="Two Bronto API keys" then="you have both keys saved somewhere safe.">

In Bronto, go to **Settings → API Keys** ([docs](https://docs.bronto.io/Account-Management/API-Keys)) and create:

- an **ingestion** key: your agent sends its telemetry with it;
- a key that can **create dashboards**, used once in Track A to build the LLM dashboard.

</Step>
</Steps>

## 2. Your LLM

<LLMTabs>
<Tab label="AWS Bedrock">

Amazon Bedrock, paid from your AWS credits. The labs only use models that need **no access form**: Amazon Nova 2
Lite and OpenAI's gpt-oss-120b.

<Steps>
<Step n="2.1" title="An AWS account" then="you can sign in to the AWS console.">

Already have one? Use it. Otherwise sign up at [aws.amazon.com/free](https://aws.amazon.com/free/) and choose the
**Free plan**: **$100 in credits** straight away, and up to **$100 more** from getting-started activities. The Free
plan never charges you: when the credits run out, it stops. Turn on MFA for the root user (console → your account
name → **Security credentials**).

</Step>
<Step n="2.2" title="Earn $20: try a model in the Bedrock playground" then="the activity shows as complete in the Explore AWS widget.">

New accounts: on **Console Home**, find the **Explore AWS** widget and open *Use a foundation model in the Amazon
Bedrock playground*. Switch the console to **US West (Oregon)**, pick **Amazon Nova 2 Lite**, and send any prompt.

</Step>
<Step n="2.3" title="The AWS CLI v2" then="aws --version prints aws-cli/2.x.">

<OSTabs>
<Tab label="macOS / Linux">

macOS with Homebrew:

```bash
brew install awscli
```

Linux (x86_64; use `aws-cli-linux-aarch64` on ARM):

```bash
curl -sSL "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o awscliv2.zip && unzip -q awscliv2.zip && sudo ./aws/install
```

</Tab>
<Tab label="Windows (PowerShell)">

```powershell
msiexec.exe /i https://awscli.amazonaws.com/AWSCLIV2.msi
```

Close and reopen PowerShell after the installer finishes.

</Tab>
</OSTabs>

```bash
aws --version
```

</Step>
<Step n="2.4" title="Sign the CLI in" then="your browser says you're logged in.">

This opens your browser, signs in with your console login, and gives the CLI short-lived credentials:

```bash
aws login --region us-west-2
```

If `aws login` isn't recognised, update the AWS CLI (step 2.3). If your company signs you in with IAM Identity
Center instead, use `aws sso login --profile YOUR-PROFILE` and add `--profile YOUR-PROFILE` to the `aws` commands
below.

</Step>
<Step n="2.5" title="Check who you are" then="you see your 12-digit account ID.">

```bash
aws sts get-caller-identity
```

</Step>
<Step n="2.6" title="Check Bedrock from the CLI" then="the model replies with a short greeting.">

<OSTabs>
<Tab label="macOS / Linux">

```bash
aws bedrock-runtime converse --region us-west-2 --model-id us.amazon.nova-2-lite-v1:0 --messages '[{"role":"user","content":[{"text":"Say hello in five words"}]}]' --query 'output.message.content[0].text' --output text
```

</Tab>
<Tab label="Windows (PowerShell)">

PowerShell mangles JSON quotes passed to programs, so put the message in a file first:

```powershell
'[{"role":"user","content":[{"text":"Say hello in five words"}]}]' | Set-Content -Encoding ascii msg.json
aws bedrock-runtime converse --region us-west-2 --model-id us.amazon.nova-2-lite-v1:0 --messages file://msg.json --query "output.message.content[0].text" --output text
```

</Tab>
</OSTabs>

</Step>
</Steps>

</Tab>
<Tab label="Your own API key">

No AWS account or AWS CLI needed. Your provider bills you directly, so AWS credits don't apply; the labs use a few
cents of tokens.

<Steps>
<Step n="2.1" title="An API key from one provider" then="you have the key saved somewhere safe.">

- **OpenAI**: [platform.openai.com/api-keys](https://platform.openai.com/api-keys). The labs use `gpt-5.4-mini`.
- **Anthropic**: [console.anthropic.com/settings/keys](https://console.anthropic.com/settings/keys). The labs use
  `claude-haiku-4-5-20251001`.
- **Google**: [aistudio.google.com/apikey](https://aistudio.google.com/apikey). The labs use `gemini-3.8-flash`.

OpenAI and Anthropic need prepaid credit on the account before the key works. Google's free tier is enough.
More on models: [Your own LLM key](/byo-llm).

## 3. Docker

<Steps>
<Step n="3.1" title="Docker" then="the hello-world container prints “Hello from Docker!”.">

Docker Desktop, OrbStack, Colima or Docker Engine. Then check:

```bash
docker run --rm hello-world
```

On Linux, if you use `sudo docker`, use `sudo -E docker` in every command so your environment comes along.

## 4. Make your `.env`

<Steps>
<Step n="4.1" title="A folder and a .env file" then="the folder has a .env file in it.">

Replace the placeholders before you paste: your **ingestion key** and your **name** (lowercase, no spaces). With a
**US** Bronto account, change `eu` to `us` in the endpoint.

<LLMTabs>
<Tab label="AWS Bedrock">

<OSTabs>
<Tab label="macOS / Linux">

```bash
mkdir ai-observatory && cd ai-observatory
cat > .env <<'EOF'
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
AWS_SESSION_TOKEN
AWS_REGION=us-west-2
OTEL_EXPORTER_OTLP_ENDPOINT=https://ingestion.eu.bronto.io
OTEL_EXPORTER_OTLP_HEADERS=x-bronto-api-key=YOUR-INGESTION-KEY
ATTENDEE=yourname
EOF
```

</Tab>
<Tab label="Windows (PowerShell)">

```powershell
mkdir ai-observatory; cd ai-observatory
@"
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
AWS_SESSION_TOKEN
AWS_REGION=us-west-2
OTEL_EXPORTER_OTLP_ENDPOINT=https://ingestion.eu.bronto.io
OTEL_EXPORTER_OTLP_HEADERS=x-bronto-api-key=YOUR-INGESTION-KEY
ATTENDEE=yourname
"@ | Set-Content -Encoding ascii .env
```

Keep `-Encoding ascii`: otherwise Windows PowerShell 5.1 can add a byte-order mark and Docker misreads the first line.

</Tab>
</OSTabs>

The three bare `AWS_…` lines have no values on purpose: Docker copies them from your terminal (next step).

</Tab>
<Tab label="Your own API key">

Also replace the provider and key lines: `LLM_PROVIDER=openai` with `OPENAI_API_KEY=`, `LLM_PROVIDER=anthropic` with
`ANTHROPIC_API_KEY=`, or `LLM_PROVIDER=gemini` with `GEMINI_API_KEY=`.

<OSTabs>
<Tab label="macOS / Linux">

```bash
mkdir ai-observatory && cd ai-observatory
cat > .env <<'EOF'
LLM_PROVIDER=openai
OPENAI_API_KEY=YOUR-LLM-KEY
OTEL_EXPORTER_OTLP_ENDPOINT=https://ingestion.eu.bronto.io
OTEL_EXPORTER_OTLP_HEADERS=x-bronto-api-key=YOUR-INGESTION-KEY
ATTENDEE=yourname
EOF
```

</Tab>
<Tab label="Windows (PowerShell)">

```powershell
mkdir ai-observatory; cd ai-observatory
@"
LLM_PROVIDER=openai
OPENAI_API_KEY=YOUR-LLM-KEY
OTEL_EXPORTER_OTLP_ENDPOINT=https://ingestion.eu.bronto.io
OTEL_EXPORTER_OTLP_HEADERS=x-bronto-api-key=YOUR-INGESTION-KEY
ATTENDEE=yourname
"@ | Set-Content -Encoding ascii .env
```

Keep `-Encoding ascii`: otherwise Windows PowerShell 5.1 can add a byte-order mark and Docker misreads the first line.

</Tab>
</OSTabs>

Your `.env` now holds a secret: don't commit it or paste it anywhere public.

</Tab>
</LLMTabs>

</Step>
<Step n="4.2" title="AWS route only: put your credentials in this terminal" then="the command prints nothing (that's success).">

<LLMTabs>
<Tab label="AWS Bedrock">

Run this in every new terminal you start an agent from, and again when the credentials expire (the doctor tells
you):

<OSTabs>
<Tab label="macOS / Linux">

```bash
eval "$(aws configure export-credentials --format env)"
```

</Tab>
<Tab label="Windows (PowerShell)">

```powershell
aws configure export-credentials --format powershell | Invoke-Expression
```

</Tab>
</OSTabs>

</Tab>
<Tab label="Your own API key">

Nothing to do: your key is already in `.env`. Skip to the doctor.

</Tab>
</LLMTabs>

</Step>
<Step n="4.3" title="Run the doctor" then="it ends with “All good”.">

```bash
docker run --rm --env-file .env ghcr.io/bronto-community/track-a-agent python doctor.py
```

It makes a real call to your model (through Bedrock, or with your key) and checks that Bronto accepts your
ingestion key.

</Step>
